01 / Executive Decision

决策摘要与业务目标

业主为国内科技企业，主营软件开发；网站面向国内企业客户，承担搜索获客、技术售前、需求收集与销售转化。

采用 Astro + React 岛屿、Payload 自托管、PostgreSQL / pgvector、阿里云百炼，整体部署在国内阿里云。首期采用模块化单体业务设计，门户、管理后台和异步任务分别运行。

搜索曝光→有效访问→内容信任→技术咨询→有效线索→商机签约
目标 01

增加被发现的机会

建设服务、行业方案、案例与技术问答页面，提升相关搜索曝光、自然点击和品牌搜索。

目标 02

提高技术售前效率

AI 基于审核资料回答问题、提供引用、澄清需求，并将问题与摘要交接给销售。

目标 03

回答“谁来、怎么来”

记录匿名访问、来源、落地页、内容轨迹和咨询；留资后关联联系人与企业信息。

目标 04

回答“结果如何”

把有效线索、预约、跟进、报价、签约与流失回传，分析渠道和内容的业务价值。

建设原则

静态内容优先、业务事实由服务端确认、AI 回答有依据、转化结果可追溯。AI 服务暂时不可用时，公共内容、联系方式和普通表单仍应正常工作。

川江网站经营闭环 / 来源、行为与结果
05 / Search & Attribution

搜索增长与经营数据闭环

搜索增长与销售闭环并列为核心目标。曝光来自搜索平台、访问来自第一方采集、成交来自业务系统，三类数据关联分析。

visitor_id匿名访客
session_id本次访问
lead_id留资与线索
opportunity_id商机与结果
必须回答后台展示数据边界
谁来过？匿名编号、访问时间、页面轨迹、咨询主题；留资后的联系人与公司匿名编号不等于实名。公司与联系人由留资、登录或人工确认识别。
怎么来的？首次、本次、转化前来源；落地页、推广活动、referrer自然搜索词经常无法获取；无来源时标为“直接或未知”。
结果如何？有效线索、预约、跟进、需求确认、报价、签约金额、流失原因前端点击是意图；服务端或 CRM 成功记录才是业务成果。

搜索内容建设

服务与采购问题

围绕企业软件定制、系统集成、私有化部署、开发周期和验收等需求建设独立页面，依据企业真实能力选题。

案例与决策证据

解释问题、实施范围、约束与结果；服务页、案例和问答互相连接，给客户具体的判断依据。

采集与归因实现

  • 浏览器向同域接口发送页面及交互事件，CDN 缓存命中后仍可记录访问；记录唯一 event_id，服务端校验并去重。
  • 保留首次接触和转化前接触来源。留资后关联本浏览器历史；跨设备只有在明确身份验证后才合并。
  • 线索、预约、报价、签约由业务服务或 CRM 回传；采集缺失、爬虫及异常流量在报告中注明。
  • 原始事件按配置周期清理，长期分析使用汇总；联系人和对话记录按角色限制访问。

后台核心指标

展现 / 点击→有效访问→有效线索率→商机率→签约 / 金额
Sitemap、URL 提交和站长平台用于发现与监测，不保证收录或排名。平台指标注明时间、渠道和更新时间；获客成本需有实际渠道投入数据，归因关系不直接证明因果贡献。

06 / Critical Workflows

发布、问答与转化流程

把每一步的输入、执行状态和失败处理定义清楚，保证内容一致、回答有依据、线索不丢失。

A · 内容发布与知识同步

审核发布→版本任务→构建上线→缓存更新→知识索引

后台分别显示 CMS 发布、页面上线、知识索引三个状态。撤回和删除同步清理索引；旧版本任务不能覆盖新版本。首期 SSG 构建时延实测后确定，少量实时页面采用 SSR 与显式缓存失效。

B · AI 售前与需求澄清

中文问题→混合检索→引用回答→追问澄清→需求摘要

回答与图示

流式返回回答与来源；不足时说明缺失条件。技术示意图采用受限节点、连线和可信模板，校验后渲染为 SVG / Mermaid。

输入与预算

限制请求频率、问题长度、会话上下文和模型预算；支持超时、中止。资料作为检索数据，不作为业务操作授权。

C · 留资、预约与 CRM 同步

确认提交→线索入库→异步同步→销售跟进→结果回传

表单采用幂等键，事务发件箱与业务记录一起提交；Worker 同步 CRM，使用去重或 upsert，并记录失败和重试。没有外部 CRM 时，由内置线索与商机模块完成跟进、报价和结果记录。

销售交接包

每条线索包含来源、落地页、关联案例、咨询问题、需求摘要、评分依据和原始引用。邮箱域名只辅助填写公司，由访客确认；具体预约按可用时段与系统成功结果确认。

典型旅程：企业信息负责人搜索“MES 系统定制开发”进入案例页，询问 ERP 对接能力，收到带引用回答后提交需求。销售按来源和问题跟进，报价与签约结果回传到同一条线索。私人对话不会自动公开为 SEO 内容。

07 / Deployment & Operations

国内部署与运行保障

以阿里云国内资源为默认部署方案。应用与数据尽量就近部署；公共页面走 CDN，个性化和私有响应避免公共缓存。

运行层选型实施要求
公共分发国内 CDN + HTTPS缓存公共 HTML、图片、字体和文件；配置版本资源与页面缓存失效。
应用运行北京地域 ECS
Docker Compose + Nginx		web / cms / worker 独立进程。Nginx 对 SSE 关闭不适当缓冲，设置合理超时并验证代理链路。
托管数据RDS PostgreSQL
托管 Redis + OSS		连接权限隔离、数据库备份、文件受控访问；核验版本与 pgvector 支持。
AI 运行百炼中国内地地域地域与账号配套，密钥只在服务端；记录调用耗时、失败、用量和成本。
交付流水线国内 Git 托管 + CI Runner
容器镜像仓库		类型检查、业务验证、构建、预览、部署与回滚；保留上一可用镜像。
运行监控web-vitals + OpenTelemetry
SLS / 云监控		关联请求、任务与线索编号；监测页面性能、错误、任务积压、索引状态和预算。

四项运行保障

01 / 权限与数据

公开、私有与管理权限分开

接口校验角色与参数，保留操作记录；用户内容不进入公共缓存；简历、联系人与对话按权限和保留策略处理。

02 / 发布与回滚

代码回滚与数据迁移协同

保存上一镜像，迁移向前兼容，测试回滚步骤；不能把代码回滚等同于数据库自动回滚。

03 / 备份与恢复

恢复结果可验证

数据库与 OSS 配置备份，并进行恢复验证。数据恢复目标、频率与保留时间按实际业务要求确定。

04 / 容量与可用性

依据实际访问量扩展

上线前评估节点故障风险；按业务目标增加多实例。CDN 命中率不能证明动态业务整体高可用。

规模与费用：现阶段不预设实例型号、固定月费和可用性承诺。依据访问量、事件保留周期、AI 使用量和恢复目标配置。边缘函数仅在实测有收益时引入。

川江网站实施范围 / 上线验收与演进
08 / Delivery & Acceptance

实施范围与验收标准

一期同时交付获客基础与数据闭环。智能功能以实际资料和业务流程为边界，二期根据真实访客数据逐步增强。

阶段工作包可验收交付物
一期内容与搜索服务、方案、案例、问答；SEO 字段、Sitemap、站长监测；CMS 权限、审批与发布状态。
一期访客与转化第一方事件、来源归因、访客旅程、表单和预约；内置线索与商机；CRM 适配契约与结果回传。
一期AI 与运行保障中文混合检索、带引用问答、需求摘要与受控图示；性能、错误、任务、成本监控及回滚验证。
二期推荐与 Agent规则推荐与 A/B；能力、资料、预约 API；支持客户端的 WebMCP 适配，不影响普通网页入口。
按需生态与招聘有 API 产品时提供 OpenAPI 文档、沙盒、密钥与用量；按招聘规模提供匹配建议，人工决策；预留 i18n。

端到端业务验收

搜索 → 留资

HTML 正文、落地来源、事件关联、有效线索、重复提交与访问权限。

问答 → 预约

中文召回、引用支撑、无资料处理、摘要、预算和预约真实状态。

线索 → 结果

CRM 失败重试、跟进、报价、签约 / 流失回传及来源报告。
